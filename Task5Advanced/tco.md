# Задание 5. Проектирование технологического стека и расчёт стоимости

Разработайте экономическое обоснование трансформации, описав модель TCO (Total Cost of Ownership) для текущей и целевой архитектуры. Укажите основные статьи затрат, включая инфраструктуру, лицензии, сопровождение, время аналитиков, и сравните их на горизонте трёх лет.

---

Текущая архитектура на базе устаревшего DWH (SQL Server 2008) и шины Apache Camel достигла пределов масштабирования: время формирования сложных отчётов измеряется часами, подключение новых направлений требует месяцев, а стоимость сопровождения растёт экспоненциально с объёмом данных.

Предлагаемая трансформация в событийную платформу на базе Kafka и двух Lakehouse (Analytical и Medical) позволит:
    - Сократить TCO на 32% за 3 года (с учётом инвестиций в миграцию)
    - Уменьшить время аналитиков на 45% за счёт Self-service портала
    - Снизить time-to-market новых отчётов с месяцев до дней
    - Обеспечить масштабирование без кратного роста затрат

---
Горизонт расчёта: 3 года
Единица оценки: млн рублей (условные)
Категории затрат:
    - Инфраструктура (серверы, СХД, облачные ресурсы)
    - Лицензии и ПО (коммерческие и open source с поддержкой)
    - Персонал (администрирование, разработка, сопровождение)
    - Время аналитиков (ожидание отчётов, непроизводительные затраты)
    - Миграция и обучение (инвестиции в трансформацию)
---
## 1. Текущая архитектура (As-Is)

- DWH на SQL Server 2008 (поддержка Microsoft прекращена, используется расширенная платная поддержка)
- Шина Apache Camel (самописные адаптеры, сложное сопровождение)
- PowerBuilder для интерфейсов операторов
- Кастомизации поверх Power BI
- Инфраструктура: физические серверы в ЦОД (устаревшее оборудование)

## 2. Целевая архитектура (To-Be)

- Kafka (событийная платформа, управляемый кластер)
- Два Lakehouse: Analytical и Medical (MinIO + Iceberg)
- Airflow для оркестрации, Spark для обработки
- Ranger + Keycloak для безопасности
- Self-service: Dremio + DataHub
- Инфраструктура: Kubernetes в облаке (AWS/Azure/GCP) с резервированием

Основные изменения в затратах:
- Отказ от физического ЦОД -> сокращение на сервера и СХД
- Отказ от коммерческой СУБД SQL Server
- Open Source с поддержкой Kafka, MinIO, Dremio (дешевле Oracle/SQL Server)
- Администраторы БД не нужны в облаке
- ETL/Camel разработчики - Camel уходит, ETL автоматизируется
- Отказ от PowerBuilder  -> не нужна поддержка
- Затраты на Data Platform Engineers, DataOps / SRE, Data Stewards, на новые компетенции
- Снижение непроизводительных затрат: ожидание отчётов меньше, Near-real-time, Self-service
- Снижение непроизводительных затрат: ручная выгрузка делает с помощью портала самообслуживания

### 7. Выводы и рекомендации
Экономическая эффективность:

- Снижение TCO на 108.5 млн руб. (23%) за 3 года

- ROI инвестиций в трансформацию: 300% за 3 года

- Срок окупаемости: 9 месяцев после миграции

Ключевые факторы экономии:

- Отказ от устаревшего коммерческого ПО (SQL Server)

- Переход в облако (снижение CAPEX)

- Автоматизация и Self-service (высвобождение времени аналитиков)

- Сокращение персонала на поддержку легаси

Стратегические выгоды:

- Масштабирование без кратного роста затрат

- Соответствие регуляторным требованиям (PHI защищены)

- Возможность монетизации ИИ-сервисов и новых продуктов
